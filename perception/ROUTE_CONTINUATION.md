# 连续前方车道参考

2026-10-03，路线实现标识 `successor-continuation-v2`。使用已有 HDMap API，适用于唯一、连接正常的前进车道段；不写入场景编号或固定弯道坐标。首版于 2026-10-01 修复仅使用当前车道段的问题；本版补充采样接头容差及目标所属车道段的范围。

## 接口与职责

`RouteManager.update(ego) -> LaneContext` 的签名保留。以下字段由队长在公共合同增补；感知负责查图与方向归一化，规划负责采样及速度安排，控制仍消费 `Trajectory`。

| 字段 | 含义 |
| --- | --- |
| `center_line`、边界、邻道、标线、`lane_id` | 仍只描述当前车道；用于车辆误差、灯控距离和目标车道归属 |
| `forward_reference` | 世界坐标米的 XYZ 点列，原样的当前中心线作为前缀，随后是方向与连接已核对的唯一后继几何 |
| `forward_lane_ids` | 参考线按行驶方向覆盖的车道 ID；第一个是当前 `lane_id` |
| `forward_lane_spans` | 与 ID 一一对应的 `{lane_id, start_index, end_index}` 列表；索引包含两端，作用于完整 `forward_reference`，相邻段共用已核对的接头点。空列表表示旧数据缺少范围 |
| `forward_reference_valid` | 已知参考几何是否可用；不是“任务路线完整”或“已通过碰撞验收” |
| `forward_reference_status` | 参考扩展终止的原因；下表区分已知终点与尚未解决的边界 |

SDK 查询使用原生 lane ID 对象，公开字段仅保留普通字符串与数值。JSON 序列化、旧快照默认值与回放重建保持兼容。规划检查当前车道前缀，用当前车道定位进度；不在后续自交或邻近路段上重新定位车辆。

## 查询与连接

- 当前中心线按 GPS 附近的方向定向；接续段按连接点的切线定向，不能拿远处车辆当前航向判断一整段弯道的方向。原始样本需要反向时，后续查询改用对应的 predecessor links。
- 只接受一个明确后继；多个分支需要路线/决策提供选择，此版不任选第一个，也不把任务稀疏路径点直接连成轨迹。
- 连接点 XY 距离不超过 0.2 m，Z 高差仍不超过 0.1 m，切线及合并后的方向变化仍不超过 0.35 rad。角度检查针对接头两侧的局部切线，不限制整条弯道的累计转角。小范围的采样接头差沿用前段端点，避免生成极短的伪转弯段；较大间隙、高度不一致、方向突变和分叉仍停止扩展。
- 本次实际缓存地图的 SDK 独立读取显示：`799_0_-1 → 764_0_-1` 的中心线采样间距为 0.157947 m，高差约为零，局部方向差为 0.084236 rad。首版 0.1 m 水平阈值拒绝该接头；0.2 m 是对此采样数据的有界工程调整，不是平台保证值或车辆物理限值。失败时另记录接头两侧位置、距离、高差和方向检查，并避免每次刷新重复输出同一故障。
- 从主车投影向前至少查询到 120 m 或一个必须停止扩展的边界。每次最多覆盖 32 个不同车道、20000 点；保留最后一段完整几何，绝不把 120 m 切口当任务终点。
- 通常沿用 0.2 s 地图刷新缓存；GPS 跨过缓存当前车道末端时立即重查，避免尚未刷新到新车道而被旧段末端卡住。
- 后继查询失败保留已知几何及当前车道信息；规划仍按已知边界停车。目标传感器缺失策略、交通灯及紧急制动判断不随这项修正改变。

| 状态 | 意义及处理 |
| --- | --- |
| `map_end` | 最后查明的车道没有后继；规划按其末端安排停车，远在视野外时继续行驶 |
| `lookahead_limit` | 已有足够前方几何且还有后继；随车辆前进继续刷新，规划的 60 m 截取末端不是停车点 |
| `ambiguous_successor` | 多个分支没有明确路线选择；在已知边界前停车 |
| `link_unavailable`、`successor_unavailable`、`successor_query_failed` | 连通信息或后继查询不可用；保留已知几何并在其边界停车 |
| `disconnected_successor` | 位置、高度或方向不符合连接检查；不跨越不明连接 |
| `cycle`、`lane_limit`、`point_limit` | 扩展遇到循环或预算上限；不无限查询，也不假设其后路径可行 |

无连续参考的旧输入继续使用当前中心线。明确 STOP 距离、零速目标、红灯和急停约束仍生效；不会为了跨车道段而抹掉停车约束。换道、路线分叉选择、闭环赛道路线展开、泊车和非空目标的障碍规划仍需各自实现。

## 跨多段的前车匹配

感知在接续成功时同步填充每个车道段的点索引范围。决策检查范围与车道 ID、当前车道前缀及完整参考线一致，然后把地图归属已核实的目标投影到它所属的车道段，并换算为完整路线上的弧长。这可以处理第二、第三个后继车道上的前车，也避免掉头路线相邻路段距离相等时匹配到另一段。

范围缺失或不一致时保持旧版保护：只有第一后继可使用既有语义，更远后继仍标未知。地图归属未核实、目标超出所属车道的覆盖范围、横向距离过大或投影有歧义时仍保护停车。失败原因现在区分覆盖范围、横向距离和多处匹配，并附带参考线状态及目标车道 ID。

目标地图归属查询另在 `Target.lane_width_m` 保留该目标当前位置的 HDMap 实测宽度；查询或归属失败时为 `None`，旧快照也默认未知。规划消费已核实的路线段及目标位置宽度，以目标所属段的局部切线检查运动，不把前车先进入后继段视作横穿，也不借用自车所在直道的宽度。横向漂移仍扩张包络，超出可用车道空间、迎面或横穿运动仍拒绝。

实际地图离线验证使用 SDK 独立加载本次缓存文件，得到与运行日志一致的 319/24/24/318 个采样点，再用合成前车位置比较修复前后。该验证不包含原运行失败帧的目标坐标，不连接案例，不发送控制；仍需平台复跑确认原症状及规划、控制响应。
