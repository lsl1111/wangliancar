# 路线信号与停车约束

2026-10-04，决策版本 `decision-constraints-v6`。按地图作用范围、所选路线和本帧状态处理所有前方信号，算法没有新增题号或固定场景坐标分支。生产链仍为 `SimOneAdapter → Perception → DecisionTarget → Trajectory → ControlOut`。

## 关联与几何事实

`getStoplineList(signal,lane)` 的道路关联不能独自证明灯适用于本车。适配层保留灯的 `validities`，核对 road/section/lane 范围；感知核对已验证的所选连接车道。灯具前向向量有效时，还须与停止线处路线方向相对。排除邻道、未选转向及另一行驶方向的灯不取决于其颜色。

完整停止横线与已验证路线求交，主车仍锚定当前中心线。缺作用范围的真实关联线保留未知适用性，不能发布可放行的绿灯；缺动态状态、冲突灯色或损坏记录也不能变成无灯。经过的有界停止线可移除，未知交点不能算已通过。

多个信号按停止边界分别组织。同一边界仅在全部适用灯本帧读取成功且颜色一致时发布有效状态；当前实现只对 `GREEN` 放行，黄灯、闪烁、黑灯和未知状态继续有停车约束。前方绿灯不会掩盖后续红灯。

## 公共字段

`TrafficControl` 增加下列字段，SDK 原生对象不进入成员接口。通用递归序列化将它们保留在 `latest_perception.json` 及刹车事件的同帧感知中。

| 字段 | 语义 |
| --- | --- |
| `signal_groups_valid` | `True` 表示已按此协议提供全部独立组；不是所有灯都可放行。`False` 保留原单灯接口语义 |
| `signal_groups` | 每组包含 `signal_ids / signal_state / valid / ambiguous / association_valid / stop_line_distance / boundary_kind / reason / count_down / signal_distance` |
| `diagnostics` | 被排除或未解析记录的 ID、关联车道及原因；必要时记录保护边界类型与距离 |

组距离单位为 m，以 GPS 后轴参考点为原点，沿同一条已验证路线累计；非负距离是前方边界，`-1` 表示边界未确定，不能解释成可越过。`valid=True` 必须有明确物理停止线和状态。空组只有在作用范围查询确认无适用信号时才成立；必需/已观察信号的空组、损坏组和不可信源不能放行。

| `boundary_kind` | 边界依据与限制 |
| --- | --- |
| `stop_line` | 与已验证路线求得的真实地图停止线 |
| `scope_entry` | 未来车道的关联查询或几何未解析时，整车须留在其已验证入口之前；不表示存在一条物理停止线 |
| `coverage_end` | 点式旧停止线输入位于覆盖之外，保留可证明的路线覆盖下界；不能外推驾驶路线或声明已定位停止线 |
| `unknown` | 当前范围缺可靠边界，保持/制动保护 |

原 `traffic.signal_state / valid / stop_line_distance / signal_id` 仅汇总最近组以兼容旧读取者；合成保护边界不会写成旧字段里的真实停止线。成员需要全路线停车条件时使用 `core.traffic_quality.signal_stop_requirement()`，不能把最近组的绿灯当作整条路线放行。

## 决策、规划和监护

三层使用同一组信号事实，按所有停车条件取最近边界。可靠边界扣除显式车头偏移与停车余量后，可在边界前正常接近；当前未知边界继续保护。信号停车边界与前车、静态目标、路线末端和限速约束共同成立，不能相互抹除。

决策输出既有模式、目标速度和停车距离。规划独立消费信号事实，即使决策漏掉已知红灯停点，也限制其轨迹；缺车身尺寸时不能自行猜测车头位置。未知信号的普通接近仍要求决策明确提供有界停车请求。

安全监护独立核对有效期、轨迹停车声明和实际逐点路线进度，拒绝缺失停车约束或越界轨迹，并产生零油门制动候选。它不是只在灯色读取失效时才检查。真实制动能力、延迟及平台物理响应仍需验收。

共享余量沿用 `NEVC_DECISION_TRAFFIC_STOP_MARGIN`，默认 0.3 m；启动时核对决策与规划一致。车头输入沿用 `NEVC_VEHICLE_FRONT_OFFSET_M`，没有为此问题放宽跟车、接头、投影或停车阈值。
