# 行为感知与正式交接：第一阶段

基线为包含决策 PR #20、规划 PR #21 的 main `aa65aeb`。复用现有
`PerceptionBuilder`、`RouteManager`、地图对象读取、目标质量检查、决策行为
状态机、前进规划器和控制器停稳计时；三个固定入口的签名保持不变。

## 已接入的事实

公共出口是 `Perception.maneuver_environment`，也随 `latest_pipeline.json`
发布。`valid=True` 只表示本帧 GPS/时效可用，不表示所有区域可通行。

| 字段 | 实际来源及语义 | 仍未知的部分 |
| --- | --- | --- |
| `neighbor_lanes` | SDK 邻道中心线、两侧边界、宽度、车道类型；核对高度、共享边界和可解析车道 ID 的方向；保留原生标线范围字段 | 标线查询只证明车旁一点，尚无整段合法跨线范围，`crossing_range_verified=False` |
| `objects` | 已有正式 Sensor 目标；世界坐标、速度、尺寸、朝向/未知朝向、来源、原始帧和独立期限 | 不把 ground truth 作为空区域证据；缺少可靠尺寸或来源时不证明清空 |
| `parking_spaces` | 复用 SDK 车位边界和朝向，完整车身与车位相交即占用；未知朝向用包围圆 | 未验证可见范围时，空目标包仍为 `unknown`；没有自动生成进出车位路径 |
| `coverage_regions` | 当前任务、案例、车辆、实际 Sensor 安装全部匹配的显式可见模型 | SDK 3.0.0001 配置不包含视场、最大范围或遮挡模型；默认没有覆盖证书 |
| `free_regions` | 仅发布完整覆盖且未与已观测车身相交的车位多边形 | 不扩成车位外的驶入区、道路或多个区域的凸包 |
| `crossing_regions` | 已有与信号/车道关联的人行横道；当前车身占用和 3 秒恒速扫掠；关联一致且与路线相交的入口停线 | 独立无灯停线、人行横道、路口冲突/出口区域及完整优先权尚无生产者 |

坐标为世界米、车身朝向为弧度。`observed_at_s/valid_until_s` 使用同一进程的
monotonic 时钟，不能跨进程直接解释。动态证据保留 Sensor 原始年龄，不能
被新 GPS 帧延长。没有对应历史车辆位姿时，较旧 Sensor 帧不用于将车身坐标
可见模型转换到世界坐标。邻道非凸边界保持原样，并进行有预算的自交检查，
不会用凸包填平弯道外侧。

## 可见模型配置

`config/default.ini` 的 `sensor_visibility_file` 默认空。示例文件
[sensor_visibility.example.json](../config/sensor_visibility.example.json) 的
`profiles` 也为空，不能直接使任何区域变成已验证。

只有来自场景 Sensor 配置和检测模型验证的记录，才应加入 `profiles`：

- 精确的 `task_id/case_id/vehicle_id/sensor_id`。
- `installation` 完整匹配实时 SDK 的 `type/x/y/z/roll/pitch/yaw/hz`，保持 SDK 原单位。
- `body_region_m` 是车辆坐标系中的凸可见多边形，x 向前、y 向左。
- `complete_detections=True` 必须意味着该区域内完整检测已验证，包括适用的遮挡条件；仅有视场参数不够。
- `verification_reference` 记录可检查的配置/验证依据。

文件无效、删除、范围不匹配、传感器重新配置、目标旧帧或读失败均撤销覆盖。
单个目标的 `range` 是该目标距离，不是 Sensor 最大探测范围。
当前离线测试用模型明确标记为合成数据，不能当作实际 SimOne 校准记录。
当前模型是二维模型；另一高度层、未知高度或坡度超出平面容差时不发布空区域
证书，立体遮挡仍需模型证据。

## 请求、规划和执行反馈

新增公共字段：

| 方向 | 字段 | 作用 |
| --- | --- | --- |
| 运行 → 决策 | `Perception.behavior_channel` | 当前任务/会话/帧的能力、独立时效和上一帧反馈 |
| 决策 → 规划 | `DecisionTarget.behavior_request/behavior_active_identity` | 正式请求及活动修订身份 |
| 规划 → 控制 | `Trajectory.behavior_identity/stop_obligation_id` | 将路径、停留与原请求/停车义务绑定 |
| 规划 → 运行 → 下一帧决策 | `Trajectory.behavior_feedback` | `PLANNED/REJECTED`，不代表已经执行 |
| 控制 → 运行 | `ControlOut.execution_observation` | 原控制器基于有效连续 GPS 计算的到点/停稳时长/停留完成；与诊断、发送回执分开 |

已将原决策协议类型移到 SDK 无关的 `core/behavior_contract.py`；原 import
路径继续转出同一类型。独立草案样例保持 `proposal_not_runtime_connected`；
正式通道显式使用 `runtime_connected`，未实现动作不会因存在公共字段被启用。

目前正式消费者支持 **信号停止点与最短停留（P07/D01）**。场景职责沿用原
决策的第 20 题选择，停点来自实际路线和信号关联，时长来自已验证设置。
本阶段未新增固定地图坐标或根据 `reason` 文本选择动作。

规划仍使用原前进路径、车辆约束和障碍保护。正距离停止目标使用已有的
有限距离前进约束，允许车辆从低速/静止继续到停点；到点后由原控制器计时。
提前绿灯不能省略尚未完成的停留；停留完成也不能越过仍为红灯的约束。
更近的障碍停止不挂上信号停留义务，不能被误认为已到灯下。

未知动作、过期/未来帧、旧修订或不同任务请求明确拒绝。曾接入的未完成
信号义务遇到通道丢失/能力撤销时保护停车，不能回到普通绿灯前进。连续
停留被漂移、运动、失效或时钟间隔中断后重新累计；新义务不能覆盖未完成
旧义务，重规划也不能缩短停留。发送成功不产生到点/完成证据，发送失败
会使执行反馈失败。

运行只声明实际接入的 `PATH_STOP/DWELL/FEEDBACK`，且控制配置可用时才
声明。当前不声明 `LANE_CHANGE/PARKING/LIGHTS` 等未完成的整条行为能力。
原控制灯光字段可以计算命令，尚无灯光实际生效证据，不能伪造确认。
