# 行为感知与正式交接：分阶段实现

基线为包含决策 PR #20、规划 PR #21 的 main `aa65aeb`。复用现有
`PerceptionBuilder`、`RouteManager`、地图对象读取、目标质量检查、决策行为
状态机、前进规划器和控制器停稳计时；三个固定入口的签名保持不变。

## 已接入的事实

公共出口是 `Perception.maneuver_environment`，也随 `latest_pipeline.json`
发布。`valid=True` 只表示本帧 GPS/时效可用，不表示所有区域可通行。

| 字段 | 实际来源及语义 | 仍未知的部分 |
| --- | --- | --- |
| `neighbor_lanes` | SDK 邻道几何、类型和车旁标线；XML 道路 s 区间与 SDK 局部共享边界核对，发布 `crossing_ranges_world`、行驶方向与局部几何 | 已验证片段不等于整车轨迹可跨线；完整侧后覆盖与候选扫掠仍需核验 |
| `objects` | 已有正式 Sensor 目标；世界坐标、速度、尺寸、朝向/未知朝向、来源、原始帧和独立期限 | 不把 ground truth 作为空区域证据；缺少可靠尺寸或来源时不证明清空 |
| `parking_spaces` | 复用 SDK 车位边界和朝向，完整车身与车位相交即占用；未知朝向用包围圆 | 未验证可见范围时，空目标包仍为 `unknown`；没有自动生成进出车位路径 |
| `coverage_regions` | 当前任务、案例、车辆、实际 Sensor 安装全部匹配的显式可见模型 | SDK 3.0.0001 配置不包含视场、最大范围或遮挡模型；默认没有覆盖证书 |
| `road_regions` | 当前与邻道实际边界的局部切片，保持非凸轮廓，以 SDK 类型和 XML 核对道路属性；发布精确三角单元及局部占用 | 只表示 SDK 折线模型；道路可行驶属性不等于行驶方向、跨线权限或未来无碰撞 |
| `free_regions` | 完整覆盖的空车位，以及道路单元与已验证可见区域的凸交集；与已观测完整车身相交的区域不发布为空 | 不外推未知部分，不合成区域凸包；这是当前占用证据，不是未来轨迹证书 |
| `crossing_regions` | 已有与信号/车道关联的人行横道；当前车身占用和 3 秒恒速扫掠；关联一致且与路线相交的入口停线 | 独立无灯停线、人行横道、路口冲突/出口区域及完整优先权尚无生产者 |
| `map_semantics` | SDK 选中地图的身份、MD5、文档解析状态；当前车道的道路 s 与分段核对 | 不能以相同文件名、旧缓存或地图加载成功代替文档身份匹配 |
| `junctions` | 当前已验证路线经过的路口、声明的车道连接/优先级、实际路线入口和出口参考点；以 SDK 道路 s 核对接头 | 入口不是停车线；冲突走廊、完整动态覆盖、通行优先权与出口空闲仍未知 |

坐标为世界米、车身朝向为弧度。`observed_at_s/valid_until_s` 使用同一进程的
monotonic 时钟，不能跨进程直接解释。动态证据保留 Sensor 原始年龄，不能
被新 GPS 帧延长。没有对应历史车辆位姿时，较旧 Sensor 帧不用于将车身坐标
可见模型转换到世界坐标。邻道非凸边界保持原样，并进行有预算的自交检查，
不会用凸包填平弯道外侧。

## 当前地图文档与语义区间

适配层仅在已核实的 SDK **3.0.0001**、512 字节 Map 结构布局上调用
`SoGetHDMapData`。加载地图前后核对同一身份，初始化时查找本机 SDK 地图
缓存；找不到匹配摘要时才从 SDK 提供的 HTTP(S) URL 读取。文档上限 16 MiB，
拒绝重定向、压缩、DTD/实体和未知编码。URL、文档和本机路径不进入公共快照。
XML 解析另有节点、深度、道路、车道和标线记录预算。

可用 `map_document_file` 指向已有本地文件，仍必须匹配 SDK 摘要；空值不选择
任意缓存地图。每帧重新检查身份，不在驾驶循环下载或重载地图。暂时读取失败
撤销语义证据，随后同一身份的成功读取可恢复；地图身份变更要求重新加载地图，
避免将新 XML 与旧 SDK 几何配对。

标线 `sOffset` 加上所属 `laneSection.s` 才是道路 s；声明有效到下一条标线或
分段末端。跨越相邻同侧车道时，由绝对车道编号较小的车道拥有共享标线，
`increase/decrease` 按数字编号判断。相关定义见
[ASAM 标线规范](https://publications.pages.asam.net/standards/ASAM_OpenDRIVE/ASAM_OpenDRIVE_Specification/v1.8.1/specification/11_lanes/11_08_road_markings.html)。
SDK `length` 不作为声明区间长度。细化、显式或偏移标线与动态方向/通行限制
尚未解释时不授权跨线；XML 与 SDK 当前类型或分段偏移不一致时也不授权。
已经证实 XML 禁止跨线时，原有车旁“虚线”观察不能覆盖这条限制。

### 局部世界边界与道路区域

共享边界核验按车辆附近固定窗口分帧推进，车辆移动不会每帧重启任务。
两侧邻道轮流使用同一预算，每帧最多 16 个原子步骤，在步骤间检查 5 ms
期限；SDK 单次调用本身的耗时不由此保证。缓存身份包含地图摘要、SDK 对象、
车道和完整原始几何。换地图、查询失败或几何变化均不能沿用不匹配结果。
预取下一窗口期间可保留旧窗口，但不提前扩大旧窗口的授权范围。

窗口内保留原始边界顶点，以不超过 1 m 的间距查询 SDK 道路 s 和对应侧标线。
共享边界双向形状、高度和顺序一致，道路 s 严格单调，XML 与 SDK 标线匹配，
且整段边缘距标线声明转换位置至少 0.25 m 时，才发布允许跨越的边界片段。
没有利用 SDK 涂漆 `length`、道路 s 插值或凸包扩大许可。`crossing_range_verified`
表示局部边界绑定已完成；禁止跨线或方向不符时仍可能为 True，但片段列表为空。

行驶方向根据道路 RHT/LHT 和车道编号核验，定义见
[ASAM 车道组规范](https://publications.pages.asam.net/standards/ASAM_OpenDRIVE/ASAM_OpenDRIVE_Specification/v1.8.1/specification/11_lanes/11_02_lane_groups.html)。
反向、双向或动态车道尚未解释时保持未知；几何能对齐不能授权逆行换道。

道路局部片段的端部切线必须完全留在原车道内，中心线必须留在局部轮廓内。
相邻线段折返、自交、含糊接头或几何工作预算超限时保持无效。三角分解保留
所有边界顶点和原轮廓面积，不填平弯道内侧。可见覆盖只与这些单元求交，
并核验当前平面与目标完整车身；未知朝向使用包围圆。长道路局部可见不要求
整条道路全部可见，也不会使窗口以外变为已知。所有动态区域沿用 Sensor
原始观察时间和期限，地图缓存不能刷新动态证据。

路口解析连接道路、入口车道链接和出口道路，遗漏、冲突或缺失链接会使
`topology_complete=False`。声明的优先级对仅作为事实，不直接设置通行权；见
[ASAM 连接道路规范](https://publications.pages.asam.net/standards/ASAM_OpenDRIVE/ASAM_OpenDRIVE_Specification/v1.8.1/specification/12_junctions/12_04_connecting_roads.html)。
入口/出口参考点复用原路线经过校验的接头，并通过 SDK `getRoadST` 核对对应
道路起点/终点及出口车道链接。无法核对时不发布已验证入口/出口门。

## 可见模型配置

`config/default.ini` 的 `sensor_visibility_file` 默认空。示例文件
[sensor_visibility.example.json](../config/sensor_visibility.example.json) 的
`profiles` 也为空，不能直接使任何区域变成已验证。

只有来自场景 Sensor 配置和检测模型验证的记录，才应加入 `profiles`：

- 精确的 `task_id/case_id/vehicle_id/sensor_id`。
- `installation` 完整匹配实时 SDK 的 `type/x/y/z/roll/pitch/yaw/hz`，保持 SDK 原单位。
- `body_region_m` 是车辆坐标系中的凸可见多边形，x 向前、y 向左。
- `complete_detections=True` 必须意味着该区域内完整检测已验证，包括适用的遮挡条件；仅有视场参数不够。
- `verification_reference` 记录可检查的配置/验证依据。

文件无效、删除、范围不匹配、传感器重新配置、目标旧帧或读失败均撤销覆盖。
单个目标的 `range` 是该目标距离，不是 Sensor 最大探测范围。
当前离线测试用模型明确标记为合成数据，不能当作实际 SimOne 校准记录。
当前模型是二维模型；另一高度层、未知高度或坡度超出平面容差时不发布空区域
证书，立体遮挡仍需模型证据。

## 请求、规划和执行反馈

新增公共字段：

| 方向 | 字段 | 作用 |
| --- | --- | --- |
| 运行 → 决策 | `Perception.behavior_channel` | 当前任务/会话/帧的能力、独立时效和上一帧反馈 |
| 决策 → 规划 | `DecisionTarget.behavior_request/behavior_active_identity` | 正式请求及活动修订身份 |
| 规划 → 控制 | `Trajectory.behavior_identity/stop_obligation_id` | 将路径、停留与原请求/停车义务绑定 |
| 规划 → 运行 → 下一帧决策 | `Trajectory.behavior_feedback` | `PLANNED/REJECTED`，不代表已经执行 |
| 控制 → 运行 | `ControlOut.execution_observation` | 原控制器基于有效连续 GPS 计算的到点/停稳时长/停留完成；与诊断、发送回执分开 |

已将原决策协议类型移到 SDK 无关的 `core/behavior_contract.py`；原 import
路径继续转出同一类型。独立草案样例保持 `proposal_not_runtime_connected`；
正式通道显式使用 `runtime_connected`，未实现动作不会因存在公共字段被启用。

目前正式消费者支持 **信号停止点与最短停留（P07/D01）**。场景职责沿用原
决策的第 20 题选择，停点来自实际路线和信号关联，时长来自已验证设置。
本阶段未新增固定地图坐标或根据 `reason` 文本选择动作。

规划仍使用原前进路径、车辆约束和障碍保护。正距离停止目标使用已有的
有限距离前进约束，允许车辆从低速/静止继续到停点；到点后由原控制器计时。
提前绿灯不能省略尚未完成的停留；停留完成也不能越过仍为红灯的约束。
更近的障碍停止不挂上信号停留义务，不能被误认为已到灯下。

未知动作、过期/未来帧、旧修订或不同任务请求明确拒绝。曾接入的未完成
信号义务遇到通道丢失/能力撤销时保护停车，不能回到普通绿灯前进。连续
停留被漂移、运动、失效或时钟间隔中断后重新累计；新义务不能覆盖未完成
旧义务，重规划也不能缩短停留。发送成功不产生到点/完成证据，发送失败
会使执行反馈失败。

运行只声明实际接入的 `PATH_STOP/DWELL/FEEDBACK`，且控制配置可用时才
声明。当前不声明 `LANE_CHANGE/PARKING/LIGHTS` 等未完成的整条行为能力。
原控制灯光字段可以计算命令，尚无灯光实际生效证据，不能伪造确认。
