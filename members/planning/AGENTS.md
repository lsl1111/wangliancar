# 路径与轨迹规划成员约束

继承根 `AGENTS.md`。本文件自然作用于本目录；`members/planning_stub.py` 及规划测试由根规则要求补充读取本文件。

## 职责与接口

- 本成员负责 path/trajectory planning：把感知数据和决策目标转换为位置、朝向、速度与时间组成的参考轨迹。
- 固定入口是 `members/planning_stub.py::plan(perception, decision)`，输入 `Perception`、`DecisionTarget`，输出 `Trajectory`/`TrajectoryPoint`，以 `core/interfaces.py` 为准。
- 算法放本目录，固定入口保持薄封装；可维护本目录文档与规划测试，不为规则作用域移动入口或修改运行调用链。
- 不直接承担 perception、decision、control 职责，不读取 SDK 绕过感知，不输出油门/刹车/转向。变道意图、停车目标及控制失效响应通过公共协议协作。
- 输入字段不足时列出所需数据及用途。确需修改公共或其他成员代码，按根规则检查所有调用方、保持最小修改并说明原因；公共字段仍由队长统一维护。

## Skill 与技术边界

- 路径/轨迹设计、实现、评审和验证优先考虑 `.agents/skills/path-planning/SKILL.md`，可显式使用 `$path-planning`；只做文字整理等任务时按相关性决定是否加载。
- Skill 提供方法，不改变本文件的职责边界。当前不引入 ROS/ROS2/Nav2；保持 Python 3.6 和现有项目技术栈。

## 规划验证与协作

- 变更前核实坐标参考点、单位、方向、有效性和时间语义；公共类里存在某字段不代表感知已填充，或控制已消费该字段。
- 对实际实现覆盖直道/弯道、主车位于路径中段、重复点、末端和无效输入；按算法检查连续性、速度/时间一致性及适用的车辆约束，不只检查返回类型或点数。
- 参考轨迹的几何检查、车辆可跟踪性和整车赛题成绩分别验证。`Trajectory.valid=False` 不代表车辆已制动，`emergency_stop` 的实际作用须与控制成员确认。
- 需求阶段、实现阶段和仿真结果分别记录；不把缺少邻道/路线/车位数据的问题用固定场景坐标掩盖。
- 可复用但尚非团队规则的经验写入 `KNOWLEDGE.md`，保留证据、版本、适用范围和待验证项；详细规划方法放 Skill，不将实验日志累积到本文件。
