## 横向微速度目标

实现位于 [obstacle_guard.py](obstacle_guard.py)。不再把所有非零横向速度都直接认定为不支持，也不将小速度直接归零：

1. 维持 Sensor 来源、有效目标、可信尺寸、前端偏移与半宽门槛；前车仍按可能停在当前位置处理。
2. 超过显式运动容差时，要求目标明确属于当前车道、车道宽度有效、目标朝向有效且投影位于已知路径段。
3. 用目标矩形朝向计算横向占宽，再检查“当前中心线距离 + 横向速度大小 × 观察时间”是否仍在剩余车道空间内。
4. 观察时间取至少 3 s，并覆盖按现有规划减速度估计的当前制动时间；可通过 `NEVC_PLANNING_LATERAL_GUARD_TIME_S` 显式调整。该数值是实验设置，不是平台标定结果。
5. 将全部估计横向位移加入横向包络；有朝向时使用矩形，缺朝向时保留圆；几何不足、可能离开车道或迎面运动仍拒绝普通移动。

它针对当前车道内的局部同向运动，假设观察窗口内横向速度不变；不包含未知横向加速度或窗口外行为，不能称为完整动态预测。后继车道没有相应宽度事实时不使用这个例外。人工配置已有运动容差仍有效，但被容差接受的横向运动也会扩大包络。

## 前方限速的提前减速

实现位于 [speed_constraints.py](speed_constraints.py)，由 [lane_planner.py](lane_planner.py) 合并到现有速度安排中。

- 只消费有效标志目录中 `source=hdmap`、`applicable=True`、`active=False` 的未来限速；速度、距离和激活标记必须一致。无法解释的非适用观测不产生限制；声称适用却损坏的输入明确拒绝。
- 观测距离以 GPS 后轴参考点为起点。规划扣除已提供的车头偏移，让车头到达标志前满足限速；这是保守的执行边界，实际评分参考点仍待核对。没有偏移时不能假称已完成这个换算。
- 限速前的速度上界为 `v² <= v_limit² + 2*a_decel*remaining_distance`。现有决策速度、弯道、目标停车和地图末端约束共同取更低值；初速度保留实测值，不瞬间跳到限速。
- 将标志对应的精确路径位置插入采样，即使它落在两个米制网格点之间也能检查；标志在本帧 60 m 视野外时仍可约束必要的提前制动。
- 达到减速度上限仍无法在标志前满足要求时，输出既有紧急制动请求；该请求不表示车辆物理上已停住。
- 对标志后的本段轨迹保留较低速度上界，不推断解除限速或擅自提速。已通过标志的当前限速仍由感知/决策按原协议处理。

限速计算以沿路径距离工作，不按场景编号或固定地图坐标分支。多标志计算使用累计最小上界，避免逐点遍历整份标志目录。

## 离线验证

新增 [tests/test_planning_constraints.py](../../tests/test_planning_constraints.py) 的 13 项针对性测试，覆盖微速度的扩大包络、车道边缘/无几何拒绝、制动观察时间、弯道局部切向、精确标志位置、视野外提前制动、不可行制动、多限速、坏来源/坏数据，以及真实地图生产者和固定 `decide → plan → compute_control` 入口。另保留并运行原有规划及障碍物串联测试。

在本机 SimOne Python 3.6 执行 `python -B -m unittest discover -s tests -v`：382 项，381 项通过、1 项因固定 E 盘 SDK 路径要求跳过；提交前复验结果相同，耗时 68.179 s。高密度的 1500 个适用标志/1561 个输出点合成输入耗时约 10.7 ms（单次本机测量），不能代表全部循环或真实 SDK 用时。

按 owner 原始事件间隔回放全部 56 帧：旧资料中微横向速度组轨迹有效 2/8，本阶段为 8/8；其他六组仍各为 8/8。全部帧的控制候选也有效，切入和输入失效等序列仍含保持/紧急请求，不能把“有效”都理解为普通前进许可。回放受控重构进程内截止时间并保留输入的来源/年龄/质量，不证明真实数据新鲜，不调用 SDK 或发送控制。

2026-10-02 本阶段验证时，真实目标源、车辆实例、制动响应与噪声尚未验收。因此上述结果只证明合成输入下的接口、几何与约束表现，不证明跟车赛题成绩；后续正式 Sensor 证据与当前缺口见本文件顶部状态更新。
