# 带目标的前进轨迹约束

2026-10-01。固定入口仍为 `plan(perception, decision)`；本轮在原车道参考轨迹上增加保守障碍物停车约束，没有改变公共接口、SDK 接入或控制发送开关。

## 能处理什么

- 对新鲜且可用的 Sensor API 目标，使用目标长宽的外接圆包络；沿实际参考线的**每一段**寻找车身扫掠区域首次接触包络的位置。将后轴到车头距离和停车余量从该位置扣除，取最近目标作为停车上限。
- 同车道静止或沿路径前进的目标可以产生“先起步、再减速到停车点”的点速度轨迹。沿路径前进的目标按**可能立即停在当前观测位置**处理，不假定它会维持当前速度。轨迹仍会每帧重算。
- 已知尺寸、位于扫掠区域之外的邻道目标不强制停车。当前车道内已核对归属的目标，横向微速度可按下文检查并扩大包络；不能在观察窗口内留在车道的横向运动、迎面运动、无效尺寸/来源或不可行减速仍走制动/失效出口。
- 决策的 `FOLLOW` 速度仍是上限；规划根据当前自车速度与障碍物停车点安排逐点加减速。`STOP` 的停车位置未知（`stop_distance=-1`）时，静止保持，在动请求紧急制动，不编造位置。

## 必需车身尺寸

GPS 坐标是后轴中心。带目标的移动轨迹必须同时配置：

- `NEVC_VEHICLE_FRONT_OFFSET_M`：后轴中心到车头最前端，米。
- `NEVC_VEHICLE_HALF_WIDTH_M`：车身最大宽度的一半，米。

2026-10-02 集成更新：用户提供的 SimOne-Car 主车预设为轴距 291.87 cm、车头到前轴距离 100 cm、车宽 180 cm。`scripts/StartCaptain.bat` 默认传入后轴到车头距离 **3.9187 m** 和车身半宽 **0.9 m**，保留调用环境已有覆盖，并记录实际配置。它们来自该主车预设，不是测试中的合成尺寸；更换车型须重新核对。规划内部仍不编造尺寸，直接运行 `main.py` 须自行设置相同环境变量，缺失时目标非空的移动轨迹仍明确拒绝。SimOne 车身字段 `axisDistance`、`frontToFrontAxis`、`chassisWidth` 的换算分别为 `(axisDistance + frontToFrontAxis)/100` 与 `chassisWidth/200`；不要把轴距本身作为车头偏移。尺寸配置与制动响应标定是两项独立验证。

其他可显式覆盖的实验参数为 `NEVC_PLANNING_OBSTACLE_MARGIN_M`（默认 4 m）、`NEVC_PLANNING_LATERAL_MARGIN_M`（默认 0 m）、`NEVC_PLANNING_MOTION_TOLERANCE_MPS`（默认 0 m/s）和 `NEVC_PLANNING_DECELERATION_MPS2`（默认 2 m/s²）。决策也读取同一个 `NEVC_VEHICLE_FRONT_OFFSET_M` 来计算目标净距与停止线距离；`NEVC_DECISION_FRONT_OFFSET_M` 是决策侧显式覆盖项，联调时不要与规划值设成不同数值。所有参数都需结合真实车辆尺寸、传感器噪声和制动响应验证；本轮不修改这些默认值。

2026-10-02 增加局部横向位移检查，默认运动容差仍为 0。对归属已核实的当前车道目标，核对真实车道宽度、投影范围和目标朝向，以目标矩形在车道横向的占宽加上 `abs(横向速度) * 观察时间` 检查是否仍能留在当前车道。观察时间取 `max(NEVC_PLANNING_LATERAL_GUARD_TIME_S, 当前自车速度/规划减速度)`；新参数默认 3 s，是待验证的实验窗口，不是实测噪声或物理响应。接受后把整段横向位移加入外接圆包络，不将它丢弃为“噪声”。显式设置运动容差时也会扩大包络；超过容差而缺车道几何、可能离开车道或迎面运动仍拒绝普通移动。

## 已知限制与验证

外接圆和静态停车边界较保守，会比实际矩形车身更早停车。局部横向检查假设观察时间内横向速度不变，不预测加速度、后续切入、横穿、倒车或突然反向，也不证明控制能在指定距离内刹停。非空目标流来源不可信、车身尺寸未配置或目标尺寸缺失时不会放行；无目标的现有车道场景保持原流程。规划无效时由运行监护决定是否产生刹车候选，实际发送仍需团队按现有流程开启控制与安全制动。详细边界和验证见 [前进规划第二阶段](FORWARD_CONSTRAINTS.md)。

离线算法测试使用**显式的合成车身尺寸和踏板映射**，覆盖静止前车起步后停车、连续向前运动的前车、邻道车、弯道相交、横穿/迎面目标、未知尺寸、未知停车点，以及真实决策→规划→控制入口的闭环模型。启动脚本测试另核对用户主车尺寸的默认值与覆盖逻辑。合并后的主分支已在 SimOne Python 3.6 下通过 325 项离线测试；这不等于 SimOne 场景通过。现场仍需取得正式目标源的连续观测，记录目标尺寸、车头净距、停车误差和刹车响应；已有全场景真值诊断不能替代该验收。
