### R01：正式目标源

- 提供脱敏后的当前案例/任务标识、代码提交、SDK 版本、实际主车资源/版本/模式、传感器 ID/类型/范围/朝向/刷新率和配置来源。不要复制带连接凭据的完整平台原始配置。

- 验收：有目标事件能实际观测目标 ID、尺寸、朝向、世界位置/速度和车道归属；有效空帧保持有效，丢失/重复/回退/恢复保持原质量事实。不能将 `ground_truth` 改写成 `sensor:*`。
- 字段样例：[current_frame.synthetic.json](examples/current_frame.synthetic.json)。它是手写合成帧，`sensor:demo_fusion` 不是已接通的设备。

### R02：车辆与响应

- 先核对预设是否用于本次任务；未确认时在 [recording_manifest.template.json](examples/recording_manifest.template.json) 保留 `null/false`，不可自动将安装包预设提升为实测值。
- 控制成员给出试验条件（速度、坡度、车型、载荷/路况等）、指令和反馈时间、反馈速度/有符号加速度/方向/踏板/转向及实际停车位置；队长保留 SDK 发送回执和实际采样频率。
- 输出可靠工作范围内的可用减速度、转向曲率/前轮角关系、延迟及测量依据；候选输入列见 [vehicle_response.template.json](examples/vehicle_response.template.json)。该空模板没有任何实测结论。

### R03：评分与停车口径

- 请确认当前案例采用哪版规则/裁判，以及跟车净距是车体最近点、后轴坐标差还是沿路径距离；红灯/限速参考点为车头还是 GPS，泊车位置/朝向误差与停留起止如何认定。
- 本地 2025 资料已知跟车小于 10 m、停走大于 50 m、红灯停后距线大于 1 m、AEB 停后距前车大于 3.5 m 等失败条件。仍缺当前实例的适用确认和实际测量方式，不将这些阈值统一用于所有业务。
- 用逐帧参考/最终分数对照当前决策净距与轨迹停车边界；由决策确认业务余量、规划执行车体换算、控制确认跟踪误差，记录每个余量只扣一次的责任。
- 评分元数据和未知项见 [recording_manifest.template.json](examples/recording_manifest.template.json)；没有成绩时必须为 `null`，不能填“通过”。

### R04：连续事件包与参考数据

- 首批覆盖：无障碍基线、直道/弯道/坡道稳定跟车、前车制动停车再起步、切入切出、红灯加近障碍/灯色切换、目标源重复/失效/恢复。每个事件从触发前开始，持续到稳定恢复或终止；不规定一个能替代全过程的固定帧数。
- 建议包结构为 `manifest.json + frames.jsonl + events.json + scores/measurements`。JSONL 是每行一帧的 JSON，方便连续回放；这些是交付格式建议，不是已增加的生产记录器。
- `frames` 每帧应包含现有 `perception/decision/trajectory/control` 原始序列化结果和运行层监护/发送结果，记录 SDK 原始时间、已核对单位与单独的相对秒数。派生净距和参考数据注明计算方法、参考点与来源，禁止缺失字段静默补零。
- `events` 给时间区间、目标/地图对象 ID、预期行为、实际结果和评分；GT 优先核对几何与事件，不要求开工前交完整专家轨迹。它必须与正式 Sensor 输入分开，标注允许用途和覆盖范围。
- [当前帧样例](examples/current_frame.synthetic.json) 只演示字段。真实采集仍需另外交付完整轨迹/控制/监护/发送记录，不能重复这个帧当作连续数据。
- 真实原始包保存于忽略的 `runtime_data/` 或团队共享位置，在 Issue 提供位置/访问方式和校验摘要；不提交 SDK、DLL、凭据或整份平台配置到公共仓库。

### R05：反馈与恢复合同

- 由队长、决策、规划、控制共同确认：意图/阶段标识、对应输入帧与时间、输出组件、状态/原因、保持/制动请求、是否可重试、到点/静止/停留完成，以及结果的有效期/消费顺序。
- 决策负责恢复和下一阶段选择；规划拒绝或控制无效不等于车辆已停稳，运行发送成功也不等于动作完成。

### R06：邻道与连续路线

- 对每个候选车道提供有序中心线、左右边界、适用段宽度、可跨越标线/方向、连接及覆盖范围；路线明确每段从起点累计的弧长区间。弧长是沿路线累计的行驶距离，不是两点直线距离。
- 分叉由决策给选定分支，回环由上游给进度/匹配信息；队长确认地图对象版本和有效性。当前 `forward_reference` 仅核对唯一后继，不作为任意分叉规划许可。

### R07：行为目标

- 请求决策给出可执行的单阶段目标：任务/意图 ID、阶段、目标车道/车位、后轴目标位姿（位置与车体朝向）、行驶方向、速度上限、停车/最短停留/驶出条件和灯光意图。
- 一段轨迹只有一个方向，速度为非负大小，倒车不改变车体 heading 定义；换向前由控制确认停稳，下一段由决策明确授权。现有 `Trajectory.motion_direction/precision_stop/hold_duration_s` 可复用，无需重新发明方向消费者。
- `maneuver_goal_proposal` 见 [协议讨论样例](examples/protocol_proposals.synthetic.json)；其中 `REVERSE_ENTRY` 等候选阶段不属于现有 `DecisionMode`。本次不修改 `core/interfaces.py`，也不把未知 JSON 字段直接塞入生产 `DecisionTarget`。

### R08：泊车可通行区域与后方观测

- 已有车位四角/入口/朝向来自 HDMap；还需实际占用、周边障碍、后方传感器范围/盲区、帧龄和可用性，不能因为静态目录 `valid=True` 就认定可倒入。
- 需要队长明确无有效道路车道时应满足哪种自由空间质量门槛；自由空间指车辆实际可通行区域。用经核实的替代参考与观测能力支持泊车，不删除运行层既有安全条件。
