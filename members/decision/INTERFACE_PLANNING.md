# 决策 ↔ 规划 接口确认清单

决策基础版 V1 已提交（PR #4）。这份清单列出**需要规划组确认或回应**的接口项，按优先级排列。每项都写明了当前的暂定行为，便于直接回复"同意"或给出不同结论。

回复方式：在 PR 里评论，或直接改本文件的"结论"列。

## A. 阻塞联调（需要明确结论）

### A1. `STOP` 停车余量由谁扣？

**当前暂定**：决策侧扣除。`decision.stop_distance` 输出的是**已经从障碍物/停止线扣掉余量**的距离（默认 `obstacle_stop_margin=3.0 m`、`traffic_stop_margin=3.0 m`）。

**依据**：`core/interfaces.py` 对 `stop_distance` 的定义是"沿当前车道中心线到停车点的距离，参考点为 GPS 位置"——也就是**已经就是停车点**，不含余量。

**风险**：如果规划侧在 `STOP` 模式下**再扣一次**车头余量，实际停车位置会比预期远 3 米。你们 `BASELINE.md` 停车表里写的是"不再额外减一次车头余量"，与当前实现一致，但这句话在 V1 之前写下，需要你们确认仍然成立。

**需要回复**：

- [ ] 同意：`STOP` 模式下规划不再扣减，直接采信 `stop_distance`
- [ ] 不同意：请给出规划侧要扣的量和原因，我改成决策不扣

### A2. `FOLLOW` 目前会被规划拒绝

**当前事实**：`lane_planner.py:219-220` 在 `perception.targets` 非空时直接 `valid=False`。而决策 V1 在**同车道且经地图核实**的前车存在时输出 `FOLLOW`（前车在安全车距外时目标速度可大于 0）。

**后果**：只要视野里有同车道前车，决策给 `FOLLOW` → 规划拒绝 → `Trajectory.valid=False` → 不发控制。**跟车能力在当前组合下完全无法闭环验证**，虽然不影响安全性。

**需要回复**（可多选）：

- [ ] 已知悉，等规划接入避障后再验证跟车，本轮不做处理
- [ ] 希望决策在规划不支持避障期间**降级为 `STOP`**（保守停车而非跟车），避免链条必然失败
- [ ] 其他安排：______

> 说明：第二个选项我可以实现，但它会让车在遇到任何前车时直接停下，赛题里跟车类场景（14/15/22/25 等）就拿不到分。当前实现选择输出 `FOLLOW` 是为了**把决策能力先交付、由链条自己拦住**，而不是让决策假装不会跟车。请你们判断哪个更符合联调节奏。

### A3. 轨迹点数与长度要求

**当前事实**：`PlannerSettings` 用 `spacing=1.0 m`、`horizon=60.0 m`，即单帧最多约 60 个点，上限 2000 点。

**决策侧需求**：无特殊要求，决策不消费轨迹。但需要知道**控制组**要的密度，因为规划改密度会影响控制。如果你们和控制组已经定了，请在此记录结论，避免我按错误假设写文档。

**需要回复**：轨迹密度/长度是否已有结论？______

## B. 需要补的反馈通道（不阻塞，但建议尽早定）

### B1. 规划失败如何反馈给决策

**当前事实**：**没有反馈通道。** 规划返回 `valid=False` 并写入 `errors`，但决策拿不到，会在下一帧继续输出同样的目标和速度。`runtime.py` 只记录不干预。

**后果**：如果规划因为某个几何原因持续失败（例如 `lane.valid` 时好时坏、参考点投影失败），车辆会一直"有决策、无轨迹"，看起来像感知问题，实际是规划拒绝。

**这是公共接口层面的缺口**，按规则需要队长统一决定，不是我能单方面加的。当前我的缓解手段是：决策把失败原因写在 `reason` 里、`runtime.py` 会把两级输出都写进 `latest_pipeline.json`，所以**现场排查时请同时看 `latest_pipeline.json` 里 `trajectory.valid` 和 `trajectory.reason`**，不要只看决策。

**需要回复**：

- [ ] 暂不增加接口，靠 `latest_pipeline.json` 人工排查
- [ ] 建议加（需要走队长的公共接口流程）：______

### B2. 变道与路口几何

**当前事实**：决策 V1 **不产生变道**，`target_lane_id` 始终保持当前车道。规划对 `target_lane_id != lane.lane_id` 直接 `ValueError`。

**结论**：两边一致——在感知提供邻道完整几何之前，变道类场景（16/17/26/27/28/29）双方都无法支持。**这不是缺陷，是一致的边界。**

**需要回复**：是否同意在拿到邻道几何前**不推进变道**？______
