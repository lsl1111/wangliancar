# 通用前进轨迹控制算法与接入状态

控制器按统一轨迹跟踪，**不根据场景编号切换算法**。输入是同一世界坐标系中以 GPS 后轴为参考点的前进轨迹；`members/control_stub.py` 的 `compute_control(perception, trajectory)` 签名不变，运行层在启动时注入控制配置。控制模块不调用 SimOne API、不直接发送指令。它可以跟踪经过验证的平滑前进轨迹，包括车道内直线/弯道和横向位移；是否换道、选哪条路径由上游决策与规划负责。当前规划可沿唯一、已核对的后继车道段继续前进，整条链尚不能变道。普通倒车运动会被明确拒绝，急停使用 N 挡、零油门制动；泊车需要倒车意图、轨迹方向和低速状态的公共约定；速度受当前 30 km/h 跟踪上限和未验收的车辆响应限制。

| 轨迹/动作 | 控制层当前能力 | 整条链的限制 |
| --- | --- | --- |
| 前进直线、弯道、平滑横向位移 | 沿输入轨迹投影、预瞄转向并跟踪每点速度 | 车辆转向与踏板响应尚未现场标定；换道路径尚无上游输出 |
| 前方减速、停车、保持、再起步 | 距离/点速度约束、PI 踏板、零长度停车与保持状态 | 停车点和跟车距离由上游决定；车身包络及实际停车距离待验 |
| 紧急制动、输入失效 | 控制急停优先；运行层另有独立故障刹车候选 | 发送开关关闭时只记录候选；连接中断时不能保证制动到达 |
| 倒车、泊车 | 尚不输出有效普通跟踪；急停使用 N 挡制动 | 现有轨迹速度非负，缺少明确的倒车意图、参考方向与挡位协议 |

## 每帧处理

1. 启动时校验算法参数，再逐帧验证 GPS、新鲜度、同帧轨迹、整数挡位反馈、有限位置/航向/速度和本机单调时钟间隔。新帧必须递增；仍有效的重复帧返回无效的 `control:DUPLICATE`，不产生新的正常指令，但保留积分、上一输出和保持状态；过期、帧回退及长时间停滞仍进入故障处理。GPS 的 `gear` 是原始变速箱位置，不是控制指令的 N/D/R/P 枚举；不改写反馈、不直接复制到输出。普通前进轨迹明确请求 Drive=1，以世界速度在车头方向的投影判断实际反向运动；反馈为 2 或更高数值不因此被误判为倒车或驻车。可选传感器不参与控制入口的质量门槛，场景必需目标和车道由上游决策及运行层监护。
2. 急停标记先于普通跟踪的速度方向限制和路径几何处理：请求 Neutral=0，清速度积分、零油门和零转向，使用配置的紧急制动值。运行层保护制动同样使用 Neutral，不把原始 GPS 挡位解释成 Reverse/Parking 命令。有效的零长度急停轨迹可执行；参数未配置时输出无效，由独立安全监护处理。
3. 对规划输出的非急停零长度停车轨迹，先核对所有点都在车旁且速度为零；车辆仍在移动时使用普通制动上限，低速时使用保持刹车，油门和转向均为零。其他普通路径去除相邻重复点，并保留重复位置上的最低限速；拒绝非有限数据、过大点距、方向相反、离车过远、路径终点之后及交叉处无法确定进度的投影。将后轴投影到最近线段，以累计弧长 `s` 表示进度。
4. 沿路径前后各约 3 m 取三点估计局部路径曲率，直线沿用速度相关预瞄，弯道按 `D=max(Dmin,min(Dmax,D0+Tv·v)/(1+g·|κpath|))` 缩短预瞄。用 GPS 速度和横摆角速度预测短时后轴位置，默认预览 0.15 s，预测行程最多为实际前视弧长的 35%；缺少有限横摆角速度时关闭这项预测。从预测车体坐标用 `κ=2·y/(x²+y²)` 计算 Pure Pursuit 曲率，`δ=atan(L·κ)` 得前轮角，再按配置映射到转向百分比。预测是执行延迟的工程补偿，不是已标定的动力学模型。目标在车后或弦长过短时拒绝普通跟踪。
5. 速度参考取当前位置的轨迹点速度。在轨迹起点且全局目标为正时，向前 1 m 预览速度，并按 1 m/s² 加速度限制上升；既支持零速起步，也解决连续重规划时首点等于实测车速、PI 永远零误差的问题。轨迹内部的零速度约束不会被起点预览跳过。参考仍受前方低速点、全局目标、速度上限、停车距离和路径末端减速包络约束。曲率限速为 `sqrt(alat/|κpath|)`，不使用会突破横向加速度上限的爬行速度下限。纵向为 PI 加速度曲线前馈：从空间速度平方斜率估计 `a_ref`，限制在规划加减速度范围内，以暂定 0.5 s 系数转换到 PI 需求。停车意图禁止油门并清正积分；积分防积累同时考虑踏板幅值、变化率和刹车释放时的油门抑制。
6. 低速且参考接近零时进入 `HOLD`，解除保持需连续两帧可执行的正速度意图；远处终点停车标记不阻断再起步。参考已经接近零而车辆仍在移动时进入 `STOPPING`，使用普通制动上限并保留最近转向，不依赖已经消失的前视点。正常跟踪限制转向变化、油门上升和刹车释放速度；刹车增加、急停和故障切油不受普通速率限制。

`ControlOut.diagnostics` 随 `latest_pipeline.json` 发布状态、路径进度/剩余长度、横向及航向误差、参考速度及加速度、曲率限速、预瞄点、预测后轴位置、路径曲率、Pure Pursuit 曲率、前轮角与计算间隔。正常状态为 `TRACK`、`STOPPING`、`HOLD` 或 `EMERGENCY`；远处终点停车标记本身不会把巡航显示为 `STOPPING`。输入错误为 `FAULT_STOP`，输出无效。运行层在已开启发送时把控制无效转为独立的 `fault_stop` 刹车候选；重复 GPS 不发送正常控制，由运行层另监护停滞。发送失败、GPS 失效或连接断开时不保证车辆已经停车。

## 车型标定与发送边界

默认配置 `control_calibrated=true`、`send_control=false`、`safety_brake_enabled=false`。`control_calibrated` 是沿用的字段名，此处仅表示九个控制映射参数已配置且通过数值校验，**不表示车辆响应已经标定或允许发送**。有效的 GPS 和轨迹可产生 `ControlOut.valid=True` 的离线候选。默认值面向平台资源库中的 SimOne-Car 主车：

| INI 参数 | 含义 |
| --- | --- |
| `control_wheelbase_m=2.9187` | 平台主车预设的轴距 291.87 cm，换算为米 |
| `control_front_steer_max_rad=0.5` | 前轮角到 SDK 归一化转向的暂定有效比例；平台显示的 540° 是方向盘限位，不是此参数 |
| `control_steering_sign=-1` | 本机 SimOne SDK 附带的 Autopilot 示例对左侧路径使用负转向；现场仍需核验 |
| `control_throttle_per_mps=0.1`、`control_brake_per_mps=0.2` | PI 速度需求到踏板比例的工程初值，需按速度响应调节 |
| `control_hold_brake=0.1`、`control_emergency_brake=0.8` | 静止保持与紧急制动候选比例，停车/制动能力尚未实测 |
| `control_max_throttle=0.25`、`control_max_brake=0.35` | 普通控制的试运行踏板上限 |

若主车并非 SimOne-Car，应通过独立配置替换这组参数。先保持 `send_control=false`，分别检查直线、弯道、平滑横向位移、减速停车与再起步轨迹的诊断和转向符号；再按团队流程做低速发送验证并调整映射。正常发送及安全制动发送均要求 `safety_brake_enabled=true`，避免车辆有驱动指令却没有制动出口。软件预瞄、PI 增益、1 m/s² 起步加速度、2 m/s² 预览减速度、1.5 m/s² 弯道横向加速度上限及当前 30 km/h 跟踪上限都是待调算法参数，不能作为已验证的车辆响应。

离线回归：`E:\Sim-One\Tools\python36\python.exe -B -m unittest discover -s tests -v`。测试包括直线、弯道、横向位移、起步、停车、异常输入，以及带执行器滞后的自行车模型、连续重规划和变频循环。可重复的比较命令为 `python -B -m tests.control_benchmark`；基线、结果和适用边界见 [算法优化记录](OPTIMIZATION.md)。模型与实车不同，车辆响应、停止距离及参数仍需多个代表性场景的连续实测帧验收。
