# 通用轨迹控制算法与接入状态

控制器按统一轨迹跟踪，**不根据场景编号切换算法**。输入是同一世界坐标系中以 GPS 后轴为参考点、按行驶顺序排列的轨迹；`members/control_stub.py` 的 `compute_control(perception, trajectory)` 签名不变。横向使用支持前进/倒车的 Pure Pursuit，纵向使用 PI 和速度曲线前馈，另有停稳换挡、精确停车、最短停留和保持释放状态。控制模块不调用 SDK、不选择前车或路径。前进上限 30 km/h、倒车上限 1.5 m/s 均为工程初值，车辆响应尚待实测。新增契约、赛题动作和接入示例见 [通用动作说明](MANEUVERS.md)。当前真实规划仍只输出前进参考，倒车/泊车和非空障碍跟车路径尚需上游实现，不能把控制模型通过称为整车通过。

| 轨迹/动作 | 控制层当前能力 | 整条链的限制 |
| --- | --- | --- |
| 前进直线、弯道、平滑横向位移 | 沿输入轨迹投影、预瞄转向并跟踪每点速度 | 车辆转向与踏板响应尚未现场标定；换道路径尚无上游输出 |
| 前方减速、停车、保持、再起步 | 距离/点速度约束、PI 踏板、零长度停车与保持状态 | 停车点和跟车距离由上游决定；车身包络及实际停车距离待验 |
| 紧急制动、输入失效 | 控制急停优先；运行层另有独立故障刹车候选 | 发送开关关闭时只记录候选；连接中断时不能保证制动到达 |
| 倒车、泊车动作执行 | 显式倒车轨迹、方向切换时停稳/挂挡等待、精确停车、最短停留、手刹保持与驶出 | 泊车路线/空车位/碰撞包络由上游给出；现规划尚无生产者，停车模型通过不证明平台成绩 |
| 跟车速度变化、前车停车后再起步 | 跟踪上游动态速度轮廓与停车边界；直线和弯道启停有闭环模型覆盖 | 前车识别、期望间距和跟车速度需求仍属决策；当前规划仍拒绝有效非空目标 |
| 转向灯、危险报警灯 | 透传轨迹中的显式布尔意图，SDK 单独发送 | 上游负责动作前的灯光时序，不依据方向盘角度推断变道 |

## 每帧处理

1. 启动时校验算法参数，再逐帧验证 GPS、新鲜度、同帧轨迹、整数挡位反馈、有限位置/航向/速度和单调时钟间隔。有效重复帧返回无效的 `control:DUPLICATE`，保留控制记忆；过期/回退/长时间停滞进入故障。GPS 的 `gear` 是原始变速箱位置，不改写也不复制成控制命令。轨迹 `motion_direction=+1/-1` 明确请求 D/R；速度始终是非负幅值。方向切换先在 N 挡制动，速度不大于 0.05 m/s 连续 0.3 s 后挂目标挡，再等待 0.3 s 才可推进；实际反向速度与已挂挡意图相反时拒绝加速。挂挡等待不是平台反馈确认。可选传感器不参与控制质量门槛，必需来源由上游和运行层监护。
2. 急停标记先于普通跟踪的速度方向限制和路径几何处理：请求 Neutral=0，清速度积分、零油门和零转向，使用配置的紧急制动值。运行层保护制动同样使用 Neutral，不把原始 GPS 挡位解释成 Reverse/Parking 命令。有效的零长度急停轨迹可执行；参数未配置时输出无效，由独立安全监护处理。
3. 对规划输出的非急停零长度停车轨迹，先核对所有点都在车旁且速度为零；车辆仍在移动时使用普通制动上限，低速时使用保持刹车，油门和转向均为零。其他普通路径去除相邻重复点，并保留重复位置上的最低限速；拒绝非有限数据、过大点距、方向相反、离车过远、路径终点之后及交叉处无法确定进度的投影。将后轴投影到最近线段，以累计弧长 `s` 表示进度；几何和方向不变时用上一进度与速度/间隔限制候选范围，避免自交处跳段。仅速度变化保留进度，几何重规划重新锚定，无历史的歧义仍拒绝。可信同任务帧号回退当帧无效，后续新帧可停稳重新布防，不等待原高帧号；未完成的停留保留并重计时。上下文变化只有在 GPS 和轨迹均验证后才清旧任务状态。
4. 沿路径前后各约 3 m 取三点估计局部曲率，直线用速度相关预瞄，弯道按 `D=max(Dmin,min(Dmax,D0+Tv·v)/(1+g·|κpath|))` 缩短预瞄。倒车按行驶方向投影并使用车后目标，预瞄范围 0.8～3 m。以有符号 GPS 速度和横摆率预测后轴位置，默认预览 0.15 s，行程最多为实际预瞄弧长的 35%；横摆率不可用时关闭预测。车体坐标中 `κ=2·y/(x²+y²)`、`δ=atan(L·κ)`，再按标定映射转向，不对倒车额外翻转前轮角。目标不位于所请求行驶方向或弦长过短时拒绝跟踪；精确停车使用较小末端弦长门槛。预测是工程补偿，车辆响应仍待标定。
5. 速度参考取当前位置的轨迹点速度。在轨迹起点且全局目标为正时，向前 1 m 预览速度，并按 1 m/s² 加速度限制上升；既支持零速起步，也解决连续重规划时首点等于实测车速、PI 永远零误差的问题。轨迹内部的零速度约束不会被起点预览跳过。参考仍受前方低速点、全局目标、速度上限、停车距离和路径末端减速包络约束。曲率限速为 `sqrt(alat/|κpath|)`，不使用会突破横向加速度上限的爬行速度下限。纵向为 PI 加速度曲线前馈：从空间速度平方斜率估计 `a_ref`，限制在规划加减速度范围内，以暂定 0.5 s 系数转换到 PI 需求。停车意图禁止油门并清正积分；积分防积累同时考虑踏板幅值、变化率和刹车释放时的油门抑制。
6. 低速且参考接近零时进入 `HOLD`，解除保持需连续两帧可执行的正速度意图；倒车、精确停车和正向低速爬行使用 0.05 m/s 释放阈值，局部点速度较低但全局上限较高时同样可以起步。PI 死区缩为 `min(0.08, 0.1*v_ref)`，保留巡航死区而不吞掉低速需求。精确停车采用 0.05 m 末端余量、距离比例限速及 0.05 m/s 静止阈值；位置、路径对齐及停车边界对应的请求车体航向符合条件才开始上游请求的 `DWELL`。期间保留最短停留，提前的驶出请求不能缩短它，输入失效或漂移重新计时；手刹仅在确认静止时使用。近零参考且仍移动时 `STOPPING`，不依赖已经消失的前视点。正常跟踪限制转向变化、油门上升和刹车释放；刹车增加、急停和故障切油不受普通速率限制。

`ControlOut.diagnostics` 随 `latest_pipeline.json` 发布路径、误差、速度、曲率、预瞄、前轮角和间隔，另记录方向、有符号车速、最短停留剩余时间及是否到达停车姿态。状态为 `TRACK/STOPPING/HOLD/EMERGENCY/GEAR_STOP/GEAR_ENGAGE/DWELL`；远处终点标记本身不会显示为 `STOPPING`。输入错误为 `FAULT_STOP`，输出无效，运行层在已开启发送时生成独立故障制动。重复 GPS 不发送正常控制；发送失败、GPS 失效或连接断开时不保证已经停车。

纵向积分上限为 ±10 m，默认积分增益对应 ±2.5 m/s 的稳态需求，允许试运行映射利用已有油门上限应对持续负载；踏板饱和和变化率后的条件积分仍生效。坡度模型验证速度跟踪、下坡保持和卸载恢复，未使用未经验证的坡道前馈。反向滚动仍由有符号速度检查保护，不能据此声称任意坡度的坡起已经现场验证。

## 车型标定与发送边界

默认配置 `control_calibrated=true`、`send_control=false`、`safety_brake_enabled=false`。`control_calibrated` 是沿用的字段名，此处仅表示九个控制映射参数已配置且通过数值校验，**不表示车辆响应已经标定或允许发送**。有效的 GPS 和轨迹可产生 `ControlOut.valid=True` 的离线候选。默认值面向平台资源库中的 SimOne-Car 主车：

| INI 参数 | 含义 |
| --- | --- |
| `control_wheelbase_m=2.9187` | 平台主车预设的轴距 291.87 cm，换算为米 |
| `control_front_steer_max_rad=0.5` | 前轮角到 SDK 归一化转向的暂定有效比例；平台显示的 540° 是方向盘限位，不是此参数 |
| `control_steering_sign=-1` | 本机 SimOne SDK 附带的 Autopilot 示例对左侧路径使用负转向；现场仍需核验 |
| `control_throttle_per_mps=0.1`、`control_brake_per_mps=0.2` | PI 速度需求到踏板比例的工程初值，需按速度响应调节 |
| `control_hold_brake=0.1`、`control_emergency_brake=0.8` | 静止保持与紧急制动候选比例，停车/制动能力尚未实测 |
| `control_max_throttle=0.25`、`control_max_brake=0.35` | 普通控制的试运行踏板上限 |

若主车并非 SimOne-Car，应通过独立配置替换这组参数。先保持 `send_control=false`，分别检查直线、弯道、平滑横向位移、减速停车与再起步轨迹的诊断和转向符号；再按团队流程做低速发送验证并调整映射。正常发送及安全制动发送均要求 `safety_brake_enabled=true`，避免车辆有驱动指令却没有制动出口。软件预瞄、PI 增益、1 m/s² 起步加速度、2 m/s² 预览减速度、1.5 m/s² 弯道横向加速度上限及当前 30 km/h 跟踪上限都是待调算法参数，不能作为已验证的车辆响应。

离线回归：`E:\Sim-One\Tools\python36\python.exe -B -m unittest discover -s tests -v`。测试包括直线、弯道、横向位移、起步、停车、异常输入，以及带执行器滞后的自行车模型、连续重规划和变频循环。可重复的比较命令为 `python -B -m tests.control_benchmark`；基线、结果和适用边界见 [算法优化记录](OPTIMIZATION.md)。模型与实车不同，车辆响应、停止距离及参数仍需多个代表性场景的连续实测帧验收。
