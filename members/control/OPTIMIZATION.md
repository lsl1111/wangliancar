# 通用控制算法优化记录

日期：2026-09-30。修改前基线：`f5184dd`。输入仍为 `Perception + Trajectory`，固定入口不变，控制算法没有按题号分支。

## 已复现并修复的问题

| 触发条件 | 修改前行为 | 修改后行为 |
| --- | --- | --- |
| 保持停车后，收到带远处终点停车标记的行驶轨迹 | 因 `stop_required` 无法释放 `HOLD` | 用正目标和可执行参考速度释放，保留两帧确认 |
| 连续重规划，轨迹首点一直等于实测车速 | 起步后 PI 零误差，停留在很低速度 | 轨迹起点采用受加速度限制的空间速度预览 |
| 重复但仍有效的 GPS 帧 | 清积分和上一输出，影响速度和转向连续性 | 不输出新正常指令，保留控制记忆；过期仍失效 |
| 停车意图到达时仍有正积分 | 可能继续给油门 | 停车清正积分，最终输出强制零油门 |
| 接近路径末端，车速尚未为零 | 前视点过短导致输出无效 | 明确进入制动状态，不依赖前视几何 |
| 零速度约束位于路径内部 | 被起步预览绕过 | 起点以外不使用起步预览 |
| 油门受到变化率或刹车释放约束 | PI 仍积累被抑制的需求 | 在最终踏板限幅和互锁后进行条件积分 |
| 很小的曲率半径 | 0.8 m/s 下限可能突破横向加速度约束 | 曲率速度上限优先，无最低速度覆盖 |

横向在原有自适应 Pure Pursuit 上加入有限的后轴运动预测，默认 0.15 s；纵向为 PI 加空间速度曲线前馈，`a_ref=(v_future²-v_local²)/(2Δs)`，默认前馈系数 0.5 s。参数均为算法试运行值，尚未标定平台执行器。

条件积分考虑最终执行候选的限制，参考 [MathWorks 的抗积分饱和与执行器输出跟踪说明](https://www.mathworks.com/help/simulink/slref/anti-windup-control-using-a-pid-controller.html)。项目自行实现，不依赖 MATLAB 或第三方控制框架。

横向位移误差略有增加，仍小于 0.02 m；不宣称所有路径都改善。保持原来的偏移回正、左右转向和旋转坐标测试。新增曲线比较覆盖半径 10/25 m、速度 3/6 m/s、滞后 0.05/0.1/0.3/0.5 s；上述两类曲线的预测补偿均降低误差。

在均已修复末端制动的控制器之间比较前馈：关闭前馈时停在 19.893 m，开启时 19.602 m。控制器设置的末端余量为 0.5 m，所以测试参考停止位置是 19.5 m；前馈使该模型的停止位置误差由 0.393 m 降为 0.102 m。这不是平台停止距离验收。

## 验收覆盖与剩余条件

`tests/test_control_regressions.py` 覆盖上述输入与状态缺陷；`tests/test_control_closed_loop.py` 覆盖转向延迟、停车、重复观测、变频循环及滚动轨迹的起步—停车—保持—再起步。全量回归仍验证发送门槛、急停优先、非有限输入和来源有效期。

默认发送开关保持关闭。本次不改变感知、决策、规划或 SDK 接口。当前规划仍只生成本车道前进轨迹；换道需要上游轨迹，普通倒车需要方向与挡位协议。真实车辆的转向比例、延迟、踏板映射及停车位置仍需现场验证；当前平台首帧原生退出问题没有因算法修改而被宣称解决。
