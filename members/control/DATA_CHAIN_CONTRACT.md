# 控制部分的数据链契约与落地顺序

检查基线：2026-09-27 的 `nevc_auto`，以当前 `Perception → DecisionTarget → Trajectory → ControlOut → SimOne` 实现为准。本文件为控制、规划和队长的联调契约；不表示控制器已实现或车辆已标定。旧的 `DESIGN.md` 写于 `d24e670`，其中关于感知加速度、轨迹来源帧、输出数值校验和日志的若干“缺失”描述已被后续代码修复，不能再按旧基线实施。

## 当前链路的实际状态

`Perception` 含自车后轴坐标、航向、水平速度、有符号纵向加速度、目标列表、地图车道、信号/停止线、各源质量、帧号及本机有效期。决策当前只做保守集成基线：保持现速、不自主起步；目标/车道源不可用时发紧急制动意图，灯或目标触发时要求停车。规划把当前车道中心线截为从车辆附近向前的参考轨迹，能传递 `stop_required`、`stop_distance`、`emergency_stop`，但**不支持换道、倒车、泊车**。控制入口始终返回 `valid=False`，平台默认 `send_control=false`。

正常输入链已做逐级类型、同帧、截止时间、有限数检查；只有 `decision.valid && trajectory.valid && control.valid` 且配置允许时才发送正常控制。队长运行层现已增加 `SafetySupervisor`：异常时它覆盖正常控制，生成**零油门、零转向、仅刹车**的候选命令，并把模式、原因、候选值和发送回执写入 `latest_pipeline.json`。安全候选要同时满足 `send_control=true` 与独立的 `safety_brake_enabled=true` 才会发送；两个开关默认均为 `false`。刹车百分比目前只是可配置的离线候选值，尚未经过车辆标定。平台发送层使用 SDK 百分比模式，挡位是自动挡枚举，灯光另由 `SoSetSignalLights` 发出。

## 控制应消费什么

| 来源 | 控制使用方式 | 必须检查/不能推断 |
| --- | --- | --- |
| `perception.frame_id/timestamp/valid_until` | 与轨迹同帧、同时间戳且未过期 | `timestamp` 是 SDK 原值，单位/时基尚未现场确认；计算循环 `dt` 用本机单调时钟 |
| `ego.x/y/heading` | 轨迹投影、预瞄点转车体坐标；GPS 点按赛题为后轴中心 | 轨迹点也必须按同一参考点定义；不能把车头或地图中心线点直接与后轴停车边界混用 |
| `ego.speed/vx/vy/acceleration/yaw_rate/gear` | 水平速度闭环、运动方向与状态诊断，之后可加前馈 | `speed` 非负，不表示倒车；`acceleration` 已是沿车头方向有符号量；GPS 回读 steering 的单位不能直接当发送的归一化 steering |
| `perception.valid`、`ego.valid`、`source_status.gps.usable` | 自车观测可信门槛 | 总 `valid` 只证明基础 GPS，不能单独证明目标、车道或交通有效 |
| `targets_valid`、`source_status.targets.usable`、`target_source` | 控制前的安全质量门槛和诊断 | 空 `targets` 仅在读取成功且新鲜时代表“没检测到”；`ground_truth` 回退不能证明指定 Sensor API 的探测范围已生效 |
| `lane`、`traffic`、`targets` | 上游决策/规划形成意图；控制可记录诊断和独立安全否决 | 正常横向跟踪以 **Trajectory** 为目标，换道时不能用当前车道 `lateral_offset` 覆盖轨迹；控制不自行选绿灯或目标车道 |
| `trajectory.points` | 世界坐标路径、每点目标速度和相对时间；几何前向预瞄与局部速度控制 | 至少两点、点序/间距/方向可信；`relative_time` 只在规划明确语义后用于时间跟踪，首版优先按路径位置取速度 |
| `trajectory.target_speed` | 全局期望/停车意图的上界，按状态解释 | 当前 STOP 轨迹可出现 `target_speed=0` 但前方点速度仍大于 0，表示减速到停车点；不能把零一律解释成当帧满刹 |
| `stop_required/stop_distance` | 停车状态及沿路径剩余距离 | 当前距离从 GPS 参考点起算；不足以证明车头已停在停止线前，需车身前悬和停车余量 |
| `emergency_stop` | 最高优先级的当帧油门归零与制动请求 | 允许当前规划给出重合的两个零速点；不能将其送入普通 Pure Pursuit 求曲率 |

IMU 独立流的本机 SDK 结构没有帧头，当前 `source_status.imu.quality=timing_unknown`。毫米波、超声、传感器车道观测各有来源状态；它们不是首版 06 车道居中控制的必需输入，不能无来源地并入 GPS 或目标数值。

## 当前故障/停车传递真值表

| 输入情形 | 当前决策/规划 | 当前运行层与控制结果 | 实施含义 |
| --- | --- | --- | --- |
| GPS/总感知失效 | 决策无效，轨迹无效 | 安全监护转 `fault_stop`；只在最近可信 GPS 帧仍处于限定窗口内生成刹车候选 | 旧帧命令可能被平台拒绝，超过窗口或连接失效时**不能保证刹停** |
| 目标或车道失效，但 GPS 可用 | 决策基线仍提出紧急停车意图 | 安全监护明确改为 `controlled_stop` 候选，不透传正常油门；恢复须连续 3 个新鲜帧 | 停车百分比未标定；这是立即减速请求，不是继续盲行 |
| 当前车道前方红灯/歧义灯或障碍 | STOP、给出停车距离；规划减速/必要时急停 | 普通停车待控制成员实现；明确 `EMERGENCY_BRAKE` 意图或可信目标的近端 TTC ≤ 2 s 由安全监护输出 `emergency_stop` 候选。后者即使车道地图失效也可触发 | 不能自行把红灯距离换算为踏板；急停未做车辆响应验证 |
| 轨迹本身无效/过期 | 普通 `validate_output(..., trajectory)` 会拒绝有效控制 | 独立安全监护可在 GPS 可信时生成 `fault_stop` 刹车候选，覆盖正常控制 | 安全出口与普通轨迹验证分开，仍受独立开关与时间窗口约束 |
| GPS 帧重复 | 决策/规划/控制仍计算并写诊断 | 达到 `pipeline_timeout_ms` 后转 `fault_stop`，可尝试发送最近可信帧的刹车；此前仍不重复发送正常油门 | 同帧刹车可能被平台拒绝；须实测平台命令保持/超时行为 |
| 案例暂停/发送失败/连接中断 | 暂停时运行循环不进入控制；发送失败仅记录回执 | 不保证车辆停车 | 区分暂停与失帧，定义控制权交接；通信不可用时不能声称软件制动可达 |

## 首版控制实现顺序

1. **先固定控制输入契约。** 当前 `Trajectory` 取同一 GPS 后轴世界坐标；只支持前进挡。`FrameOutput.bind()` 的帧/时间/有效期必须保留。规划与控制约定 STOP 轨迹的局部速度、全局零速度、`stop_distance` 的优先级，以及端点/重规划/急停的表示。`valid_until` 是本进程单调时钟截止值，不跨进程重用。
2. **正常轨迹跟踪。** 控制成员在固定 `compute_control(perception, trajectory)` 入口内部保留有状态引擎：检查 GPS 与轨迹质量、计算实际 `dt`，将后轴投影到可信路径，按速度取空间预瞄；横向 Pure Pursuit、纵向 PI/停车状态机分开。先有曲率/前轮角，再用车型标定映射成 SDK steering 百分比；轴距、转向正负与踏板响应未标定前不产出可发送的 `valid=True` 控制。
3. **状态覆盖优先。** 急停或可执行故障制动当帧油门归零；停车减速、低速保持、恢复起步要有滞回和积分清零。正常输出校验有限数、油刹互斥、挡位、范围与变化率；急停不受普通油门/制动变化率限制。轨迹全在车后、点重合、跨段跳跃、倒车、参考点不明均拒绝普通跟踪。
4. **队长运行层故障出口已完成离线接线。** 它把目标/车道缺失、可信目标的近端 TTC、明确急停、轨迹失效、GPS 失效或连续重复帧分级，并在短时有效的 GPS 来源上生成刹车候选；可选传感器异常不触发停车。案例身份变化会重置并要求连续恢复帧。下一步仍需实测重复帧命令是否被平台接收、制动百分比与停车距离、暂停/恢复和控制权交接；这些未验证前保持双开关关闭。
5. **先观察，再低速联调。** 06 场景先验 GPS/车道/目标源和轨迹，再在 `send_control=false` 下记录候选转向、目标点、速度误差、状态、帧号与发送回执；最后由队长按团队约定开启低速控制，标定转向符号、角度到百分比、油门/刹车、车头停车余量。现阶段 06 仍为 `NO_DATA`，没有真实场景结论。

最小离线测试需覆盖：左右偏差与 90° 旋转后的转向方向；稀疏/倒序/交叉/重合/车后路径；从零起步、减速到零、停车保持；同帧来源/过期/帧回退；GPS 与目标失效、急停优先、无效轨迹、重复帧、发送失败。保持现有 Python 3.6 与 `send_control=false` 默认值；控制成员算法不直接 import SDK 或发送平台指令。
